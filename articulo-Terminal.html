Entendiendo la Interacción del Usuario: Construyendo una Mini-Calculadora en JavaScript

05 de diciembre de 2023

En este proyecto aprendí dos conceptos fundamentales: primero, que JavaScript trata cualquier dato ingresado por el usuario como una cadena de texto (string), y segundo, la crucial importancia de entender el objeto this y cómo se comporta de manera diferente entre las funciones de tipo flecha y las funciones tradicionales.

1. Capturando Elementos del DOM

Antes de poder interactuar con los elementos HTML desde JavaScript, necesitamos 'capturarlos'. Esto se logra comúnmente a través de métodos como document.getElementById(), que nos permite obtener una referencia a un elemento específico mediante su ID único. En nuestro ejemplo, identificamos el botón de ejecución, los dos campos de entrada de números y el área donde se mostrará el resultado en la "terminal". 


let btnEjecutar = document.getElementById("btn-ejecutar");
let num1 = document.getElementById("num1");
let num2 = document.getElementById("num2");
let salida = document.getElementById("salida-terminal");

2. Respondiendo a la Interacción: El Event Listener

Una vez que tenemos referencias a nuestros elementos, el siguiente paso es hacer que la página responda a las acciones del usuario. Para el botón 'Ejecutar', adjuntamos un 'event listener' utilizando addEventListener(). Este método espera dos argumentos: el tipo de evento que queremos escuchar (en este caso, 'click') y una función de *callback* que se ejecutará cada vez que ocurra ese evento. Es dentro de esta función donde definimos qué sucederá cuando el usuario haga clic. 


btnEjecutar.addEventListener("click", () => {
    // Aquí irá la lógica de nuestra calculadora
});

3. Procesamiento y Presentación de Resultados

Dentro de la función del evento, es donde ocurre la lógica principal. Es importante recordar que los valores de los campos de entrada HTML (``) siempre se obtienen como cadenas de texto, incluso cuando el usuario introduce números. Por lo tanto, es crucial convertirlos explícitamente a tipos numéricos (usando la función Number()) antes de realizar cualquier operación matemática. Finalmente, el resultado se inyecta en el elemento de salida utilizando la propiedad textContent, que es una forma segura de mostrar texto, y las plantillas de cadena (template literals) para construir un mensaje claro y dinámico. 


    let resultado = Number(num1.value) + Number(num2.value);
    salida.textContent = `El resultado es = ${resultado}`;

Uniendo todas las piezas, este es el código JavaScript completo de nuestro ejemplo de mini-calculadora: 


// Primero capturo los inputs de interés
let btnEjecutar = document.getElementById("btn-ejecutar");
let num1 = document.getElementById("num1");
let num2 = document.getElementById("num2");
let salida = document.getElementById("salida-terminal");

// Creo luego un evento click y como función (el segundo parámetro) le pido
// que guarde el resultado en una variable para luego inyectarlo en HTML con textContent.
btnEjecutar.addEventListener("click", () => {
    let resultado = Number(num1.value) + Number(num2.value);
    salida.textContent = `El resultado es = ${resultado}`;
});

4. La Importancia de this: Funciones de Flecha vs. Funciones Tradicionales

El concepto de this es uno de los pilares de JavaScript que a menudo genera confusión, especialmente al interactuar con el DOM o al trabajar con objetos. Entender cómo this se comporta en diferentes contextos es fundamental para escribir código robusto y predecible. La principal diferencia radica en cómo las funciones tradicionales (declaradas con function) y las funciones de flecha (=>) determinan el valor de this.

4.1. this en Funciones Tradicionales (Declaradas con function)

En una función tradicional, el valor de this es dinámico; se determina en el momento en que la función es invocada, basándose en cómo se llama.

  • Contexto global: Cuando una función se llama directamente sin un objeto asociado (miFuncion()), this generalmente se refiere al objeto global (window en navegadores, undefined en modo estricto).
  • Como método de un objeto: Si la función se invoca como un método de un objeto (miObjeto.miMetodo()), this se refiere al objeto que la contiene (miObjeto).
  • Como manejador de eventos: En un *event listener*, this se refiere al elemento HTML que disparó el evento.

Este comportamiento dinámico puede ser una fuente de errores si no se controla adecuadamente, especialmente en *callbacks* o funciones anidadas. 


const personaTradicional = {
    nombre: "Juan",
    saludar: function() {
        // En este contexto, 'this' se refiere a 'personaTradicional'
        console.log(`Hola, soy ${this.nombre}.`);

        // Problema común: 'this' se pierde en una función anidada sin contexto explícito
        setTimeout(function() {
            // Aquí, 'this' NO se refiere a 'personaTradicional', sino al objeto global (window)
            // o a 'undefined' en modo estricto. Por eso 'this.nombre' sería 'undefined'.
            console.log(`(Desde setTimeout): Hola, soy ${this.nombre} (o undefined).`);
        }, 100);
    }
};

personaTradicional.saludar();
// Salida esperada:
// Hola, soy Juan.
// (Desde setTimeout): Hola, soy undefined (o el nombre del window/global object si existe)

4.2. this en Funciones de Flecha (Arrow Functions)

Las funciones de flecha no tienen su propio enlace a this. En su lugar, el valor de this es léxico; es decir, lo heredan del ámbito circundante (su *scope* padre) en el momento en que se definen, y no cambia en función de cómo se llaman. Esto las hace muy útiles para *callbacks* y métodos donde se desea preservar el contexto de this. 


const personaFlecha = {
    nombre: "María",
    saludar: function() {
        console.log(`Hola, soy ${this.nombre}.`); // 'this' es personaFlecha

        // Una función de flecha anidada hereda 'this' del ámbito de 'saludar'
        setTimeout(() => {
            // Aquí, 'this' todavía se refiere a 'personaFlecha'
            console.log(`(Desde setTimeout con flecha): Hola, soy ${this.nombre}.`);
        }, 100);
    },
    // CUIDADO: Usar una función de flecha directamente como método puede ser problemático.
    // 'this' NO es 'personaFlecha' en este caso.
    // Hereda 'this' del ámbito global donde 'personaFlecha' fue definida.
    despedir: () => {
        console.log(`Adiós, soy ${this.nombre} (probablemente undefined si no está en global).`);
    }
};

personaFlecha.saludar();
// Salida esperada:
// Hola, soy María.
// (Desde setTimeout con flecha): Hola, soy María.

personaFlecha.despedir();
// Salida esperada:
// Adiós, soy undefined (o el nombre del window/global object si existe).

Como se observa en el ejemplo de despedir, usar una función de flecha directamente como método de un objeto puede ser contraproducente si se espera que this se refiera al objeto. Su mayor fortaleza reside en preservar el contexto de this en funciones anidadas o *callbacks*.

En resumen, si necesitas que this se refiera al objeto que llama a la función (contexto dinámico), usa una función tradicional. Si necesitas que this mantenga el valor de su ámbito padre (contexto léxico), las funciones de flecha son la elección correcta, especialmente para *callbacks* asíncronos o funciones anidadas.

Desde la selección de elementos hasta la respuesta a eventos y la manipulación de datos, estos son los bloques de construcción básicos para cualquier aplicación web interactiva.
