Construyendo a Jarvis: Un Asistente Local para Optimizar Recursos

Hola, soy IsaacG. Creé este artículo para explicar por qué y para qué creé a Jarvis. Actualmente estoy en un contexto donde tengo una PC de muy bajos recursos y quería evitar abrir páginas web que consumieran los recursos valiosos, por lo que me decidí a crear a Jarvis, un asistente que me permite crear código, editar y corregir errores, basado en el contexto general de la aplicación. Y ya sé que existen alternativas ya creadas por la comunidad e incluso de pago, pero quería tener la mía propia: Jarvis, un asistente de código local y ligero.

Su objetivo principal es evitar la dependencia del navegador interactuando directamente con la API de inteligencia artificial desde el entorno local. A continuación, detallo la arquitectura central que hace esto posible.

1. El Motor: Integración Directa mediante API

El núcleo de Jarvis actúa como un cliente ligero. En lugar de procesar información localmente o requerir una interfaz gráfica pesada, el sistema captura las instrucciones del usuario y las envía directamente a la infraestructura en la nube de Google a través de su API. Esto permite obtener la potencia de un modelo avanzado con un costo computacional local casi nulo. 


// Inicialización del cliente y conexión con la API
const modelo = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });

// Envío del prompt y captura de la respuesta asíncrona
const resultado = await modelo.generateContent(tuPregunta);
const respuesta = await resultado.response.text();

// Salida en la consola local
console.log(respuesta);

2. Modo Edición: Modificación de Archivos en Caliente

Para automatizar la refactorización o corrección de código, Jarvis implementa un flujo de operaciones de entrada/salida (I/O) en el sistema de archivos. El asistente lee el código fuente existente, lo adjunta como contexto al prompt del usuario y, tras recibir la respuesta de la IA, sobrescribe el archivo original.

Antes de solicitar la generación de un nuevo archivo, el script analiza los archivos existentes del proyecto para identificar convenciones de nomenclatura, paletas de colores y estructuras de código.

Conclusión: Jarvis demuestra cómo la creación de herramientas personalizadas puede resolver bloqueos técnicos específicos. Al trasladar la carga de trabajo a la nube y operar estrictamente desde el sistema de archivos local, es posible mantener un flujo de trabajo ágil e inteligente, independientemente de las limitaciones de hardware del equipo de desarrollo.
